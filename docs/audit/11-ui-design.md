# Аудит: UI и дизайн (тихая роскошь)

## Summary

В проекте есть зрелая дизайн-система: единый набор CSS-токенов в `globals.css` (цвета, радиусы, тени, безье, типографическая шкала) и сильная библиотека компонентов `DesignSystem.tsx` (Sheet, Button, Chip, Toggle, PageHeader, ConfirmDialog, SaveButton, StateView, Toast). Язык «тихой роскоши» считывается: один violet-акцент, стекло, тёмный фон-меш, аккуратная анимация. Но между «системой на бумаге» и реальным кодом — большой разрыv: типографические утилиты используются **0 раз**, радиус-токены **0 раз** (при 843 захардкоженных `borderRadius`), бренд-градиент скопирован инлайном 44 раза. Плюс два настоящих мобильных дефекта на основном устройстве (iPhone): поля ввода 15px вызывают авто-зум iOS, а часть стеклянных поверхностей не имеет `-webkit-backdrop-filter` и не размывается в Safari.

## Production-readiness score: 74 / 100

**Обоснование.** Визуально продукт уже выглядит дорого и консистентно для пользователя — общие компоненты (`Button`, `Sheet`, `Chip`, `Toast`, `StateView`, `PageHeader`) реально внедрены в ~28 из ~81 файлов, токены цветов и `.glass-*` применяются повсеместно, есть `prefers-reduced-motion`, `:focus-visible`, safe-area, tnum-цифры. Это уверенно выше среднего. Минус ~26 баллов: (1) два мобильных бага, видимых на iPhone (зум полей, отсутствие webkit-blur) — прямой удар по «тихой роскоши» на главном устройстве; (2) огромный объём инлайн-стилей вместо токенов = высокий риск дрейфа и дорогая поддержка при масштабировании на SaaS; (3) три разных шаблона шапок экранов (PageHeader vs самописные sticky-шапки vs кастомные h1/h2 разных размеров) — заметная несогласованность визуальной иерархии. Это не блокеры релиза, но это технический долг, который будет расти с каждым новым клубом-клиентом.

## Что сделано хорошо (не требует правок)

- `DesignSystem.tsx` — сильная база: тач-цели ≥44px, `aria-label` на иконочных кнопках, `role="switch"`/клавиатура в `Toggle`, pointer-press микро-анимации, единый `formatMoney`, корректный desktop/mobile вариант `Sheet`.
- `StateView.tsx` и `Toast.tsx` — аккуратные, токенизированные состояния loading/empty/error и нотификации; `Toast` корректно стоит над плавающей навигацией (`--bottom-nav-clear`).
- A11y-база в globals.css: `:focus-visible` с violet-кольцом, `prefers-reduced-motion` (гасит и орбы, и стаггер), premium фокус-свечение полей.
- Грамотная борьба с iOS-спецификой: фон-меш через `body::before` с `bottom:-120px` под home-indicator, нормализация `input[type=date/time]`, safe-area, `overscroll-behavior`.
- Сплит-вью «Управления» (`manage/layout.tsx`) с `display:contents` на мобиле и регулируемой шириной — элегантное решение «один компонент, две раскладки».
- Именование стекла консистентно: `glass-l1` (22) / `glass-l2` (160); непрефиксные алиасы практически не используются.

## Новые фичевые идеи (под мафия-клубы / антикафе)

- **Тема под клуб (theme accent).** Раз акцент один (violet) — добавить в настройках выбор фирменного цвета клуба (3–5 пресетов «тихой роскоши»: violet, изумруд, бронза, индиго). Технически это смена `--primary-violet` + `--gradient-brand` → если сначала сделать консолидацию токенов (#3), фича почти бесплатна и сильно усиливает SaaS-предложение.
- **«Атмосферный режим» для зала.** Полноэкранный dashboard-вид (часы пик, занятые зоны, ближайшие брони/ДР гостей) на планшете у входа — переиспользовать `StatChip` и orbs-фон. Для антикафе с почасовой оплатой — крупный таймер активных зон.
- **Бейджи статуса стола/зоны в едином стиле чипов.** Уже есть `pos-card-attention` (pulse). Добавить семантические `Chip`-статусы: «играют», «ждут счёт», «бронь через 15 мин», «ДР гостя» — единым цветовым кодом из `--pay-*`/семантических токенов.
- **Скелетоны вместо спиннеров на тяжёлых экранах.** `.skeleton` уже определён в globals.css, но используется мало — для Аналитики/списков игроков скелетон-карточки дают ощущение скорости и премиума.
- **Праздничный микро-акцент на день рождения гостя** (в POS уже есть модалка именинников `pos/page.tsx:1264`) — единый «золотой» акцент (`--pay-bonus`) и аккуратная анимация, чтобы официант не пропустил повод для апсейла.

## SaaS / мульти-клуб следствия для этой зоны

- **Токенизация = предпосылка white-label.** Чтобы продавать приложение разным клубам с их фирменным акцентом/логотипом, акцент и градиент должны идти из **одного** места (CSS-переменные), а не из 44+226 инлайн-копий. Сейчас смена бренда под клиента = ручная правка сотен мест. Консолидация (#3) — фундамент монетизации темы.
- **Единая шапка = масштабируемость экранов.** Когда у разных клубов включены разные модули (события, депозиты, лояльность), число экранов растёт. Три расходящихся шаблона шапок (#4, #5) при росте превратятся в хаос; единый `PageHeader` с вариантами сделает любой новый раздел консистентным «из коробки».
- **Мобильные дефекты бьют по первому впечатлению платящего клиента.** Владелец клуба оценивает продукт на своём iPhone за первые минуты демо. Зум полей (#1) и непросвечивающее стекло (#2) — ровно то, что подрывает позиционирование «премиум-POS» при продаже подписки. Это дешёвые фиксы с высокой отдачей на конверсию.
- **Тема под клуб как платный тариф.** После консолидации токенов «выбор фирменного цвета / лого на экране зала» — естественный апсейл верхнего тарифа подписки, почти без доп. разработки.
