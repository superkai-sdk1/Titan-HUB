# Аудит: Фронтенд apps/web (2026-06-18)

> Повторный аудит через 6 дней после серии 10–13 (12 июня). Ключевой вывод: **ни одна из находок HIGH/MEDIUM прошлого аудита не закрыта.** Долг по `any` вырос (249 → 296), всё остальное на месте. Проверял текущий код, а не доверял старым отчётам.

## Оценка: 64/100

База по-прежнему зрелая (единый StateView/nav, react-query как слой данных, защита оплаты от двойного списания и гонки с вебхуком, безопасность сессии PIN/Passkey, lock по бездействию). Но накопленный фронт-долг не уменьшается, а растёт, и на боевой кассе остаются три реальных операционных риска: хрупкий SW-update, тихая смерть SSE после блипа сети, глобальный ErrorBoundary, роняющий весь экран. Минус 4 балла к прошлым 68 — за регресс по `any` и неподвижность P1-долга при том, что продукт идёт в коммерческую SaaS-эксплуатацию (мультитенант уже в проде, HEAD ff813ca).

Метрики на 2026-06-18: ~31.2k LOC (apps/web/src), 76 файлов в `app/`, 95 файлов с `'use client'` (server-компонентов — 4: layout, page, privacy, terms), 209 `useQuery`, 163 `useMutation` (115 `onError`), **296** `: any`, **0** `next/dynamic`/`React.lazy`, **0** `React.memo`, **0** виртуализации, **0** импортов `@titan/types`, **0** `next/font`/`next/image`.

## Находки по severity

### [P1] SW-update может уронить активного кассира на ChunkLoadError
**Файл:** `apps/web/public/sw.js:15-33`, `apps/web/src/components/ServiceWorkerRegister.tsx` (весь)
**Суть:** SW делает безусловный `self.skipWaiting()` на install (sw.js:17) + `clients.claim()` на activate (sw.js:30) — новый воркер мгновенно перехватывает открытую вкладку со старым JS. При этом в `sw.js` **нет** `message`-листенера на `SKIP_WAITING`, а в `ServiceWorkerRegister` **нет** слушателя `controllerchange` и `onupdatefound` (компонент только регистрирует воркер, 23 строки). Не изменилось с 12 июня.
**Риск:** во время деплоя у кассира открытая PWA-вкладка (на iPhone живут сутками); SW claim'ит вкладку, переход на роут с lazy-чанком старого хэша → 404 → ChunkLoadError → глобальный ErrorBoundary сбрасывает весь экран в середине обслуживания. На сотне клубов это шквал тикетов на каждом релизе.
**Исправление:** (а) убрать безусловный `skipWaiting()` из install, добавить `self.addEventListener('message', e => { if (e.data?.type==='SKIP_WAITING') self.skipWaiting() })`; (б) в регистрации слушать `reg.onupdatefound` → тост «Доступна новая версия»; (в) `navigator.serviceWorker.addEventListener('controllerchange', () => location.reload())` с защитой от двойного reload.

### [P1] Live-поток SSE-уведомлений умирает после первого сетевого сбоя
**Файл:** `apps/web/src/lib/sse.ts:8-13`, `apps/web/src/components/NotificationsProvider.tsx:182-198`
**Суть:** `openSse()` берёт одноразовый тикет (TTL 60с) и открывает `EventSource`. В `onerror` (NotificationsProvider.tsx:197) стоит только комментарий `/* EventSource реконнектится сам */` — никакого `es.close()` + повторного `openSse()`. Браузер при авто-реконнекте дёргает тот же URL с израсходованным/протухшим тикетом → 401 → поток закрывается навсегда. Не изменилось.
**Риск:** после любого блипа Wi-Fi (блокировка экрана iPhone, переключение сети) кассир молча перестаёт получать живые заказы гостей до полной перезагрузки страницы. Для анти-кафе/мафия-клуба поток «гость → чек» операционно-критичен.
**Исправление:** в `onerror` → `es.close()` и через backoff (1с→2с→5с + jitter) заново `openSse()` (новый тикет). Останавливать при `document.hidden`, возобновлять на `visibilitychange`.

### [P1] Нет route-level error boundaries; единственный ErrorBoundary сбрасывает весь интерфейс
**Файл:** `apps/web/src/app/providers.tsx:9-34` (и полное отсутствие `app/**/error.tsx` — проверено: 0 файлов)
**Суть:** единственный ErrorBoundary обёрнут на самом верху дерева (providers.tsx). Любая ошибка рендера на любой странице роняет весь экран в «Что-то пошло не так» с кнопкой `window.location.reload()` (providers.tsx:23). В App Router нет ни одного `error.tsx`. Не изменилось.
**Риск:** одна ошибка во второстепенном виджете дашборда (или ChunkLoadError из P1-SW) выкидывает кассира из активного чека: теряются незакоммиченные данные модалки, шаг оплаты, корзина.
**Исправление:** `app/error.tsx` + точечные `app/pos/error.tsx`, `app/pos/[checkId]/error.tsx`, `app/manage/error.tsx`, `app/dashboard/error.tsx` с локальным `reset()`. Специально ловить `ChunkLoadError` → тихий `location.reload()`.

### [P1] Полный шрифт Material Symbols грузится render-blocking и нигде не используется
**Файл:** `apps/web/src/app/globals.css:2`
**Суть:** `@import url('...&family=Material+Symbols+Outlined:opsz,wght,FILL,GRAD@20..48,100..700,0..1,-50..200&display=swap')` тянет вариативный иконочный шрифт со всеми осями (сотни КБ). Иконки в проекте — инлайн-SVG (`components/Icon.tsx`, 1261 строка); класс `material-symbols` не встречается нигде. Плюс весь блок шрифтов подключён через render-blocking `@import` в CSS (нет `next/font`). Не изменилось.
**Риск:** прямой удар по LCP/FCP и трафику на каждом холодном старте PWA — на целевом устройстве (iPhone по мобильной сети). Бесплатный выигрыш.
**Исправление:** немедленно удалить `Material+Symbols+Outlined` из `@import`. Затем перевести Inter + JetBrains Mono на `next/font/google` с `display:'swap'`, `subsets:['cyrillic','latin']` (self-host, preload, без CLS).

### [P2] Модалка Sheet — без dialog-семантики, фокус-ловушки, Escape и возврата фокуса
**Файл:** `apps/web/src/components/manage/DesignSystem.tsx:119-446`
**Суть:** `Sheet` — базовый компонент всех форм/деталей (клиенты, меню, склад, смены). Панель — `motion.div` (≈DesignSystem.tsx:278) без `role="dialog"`, `aria-modal`, `aria-labelledby`; нет `keydown`-обработчика `Escape`, нет focus-trap (Tab уводит фокус под оверлей), нет возврата фокуса на триггер, нет автофокуса. Закрытие — только клик по оверлею/крестику/свайп. Не изменилось.
**Риск:** WCAG 2.1 (4.1.2 Name/Role/Value; фокус «протекает» в фон). Скринридер не объявляет диалог; пользователь аппаратной клавиатуры (iPad/десктоп-касса) не может закрыть по Escape. Один компонент чинит все экраны.
**Исправление:** `role="dialog" aria-modal="true" aria-labelledby={titleId}`; `Escape → onClose`; focus-trap (`inert` на фоне); сохранять/возвращать `document.activeElement`; автофокус.

### [P2] Toast без aria-live — критичные уведомления не объявляются скринридером

### [P2] Нулевое code-splitting при компонентах-гигантах

### [P2] Shared-типы @titan/types не используются — 296 `: any` на границе API (регресс)

## Хранение токенов (XSS)
JWT и superadmin-токен лежат в `localStorage` (`store/auth.store.ts` persist `name:'titan-auth'`; `lib/superadminApi.ts:20-38`). Это стандартный для SPA выбор, но при любом XSS токен утекает целиком. `dangerouslySetInnerHTML` в проекте — **0 вхождений** (хорошо, поверхность XSS мала). Отмечаю как наблюдение, не как находку: переход на httpOnly-cookie + CSRF — отдельный крупный архитектурный проект, не P-level для этого аудита. `api.ts:26` корректно делает `logout()` на 401 с токеном (хорошо).

## Что сделано хорошо (не требует правок)
- Защита оплаты от двойного списания и гонки с вебхуком Platega (CheckDetailView), `writeCheck` через `setQueryData` — мгновенный отклик корзины.
- Безопасность сессии: разблокировка строго своего профиля, lock на холодном старте, исключение планшетов-киосков; логаут не зацикливается на 401.
- SSE без JWT в URL (одноразовый тикет) — концепция верная (баг только в реконнекте).
- SW не кэширует `/api/` — данные не утекают между сменами на киоске.
- Единые `StateView`/`nav.ts`; `:focus-visible` и `prefers-reduced-motion` глобально; иконки — инлайн-SVG (нет иконочного шрифта в рантайме); 0 `dangerouslySetInnerHTML`.

## Возможности апгрейда
1. **Управляемое обновление PWA** (закрывает P1-SW): `SKIP_WAITING`-message + `controllerchange`-reload + тост «новая версия» — предпосылка безопасных частых деплоев в SaaS и фича доверия одновременно.
2. **Контрактная типобезопасность**: вынести response-типы/zod в `@titan/types`, импортировать в хуки, ввести бюджет `any` в CI. Останавливает регресс (249→296) и снимает главный SaaS-риск рассинхрона PWA↔API.
3. **Code-splitting тяжёлых поддеревьев** через `next/dynamic` (платёжные шторки, графики дашборда, drag-редактор) + `next/font` для шрифтов — снижает TTI первого запуска кассы на 4G.
4. **Офлайн-устойчивость**: `app/offline/page.tsx` + прекэш, route-level `error.tsx` с изоляцией ChunkLoadError, SSE-реконнект с backoff — кассир переживает блипы сети и деплои без потери активного чека.
5. **Tenant-aware кэш (на будущее, упреждающе)**: при мультитенанте включить `clubId` в queryKey (`['checks','active', clubId]`) и в `name` persist-стора, чтобы кэш одного клуба не «протёк» в другой на общем устройстве.
