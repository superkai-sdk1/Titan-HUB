# Аудит: Продукт, фичи и монетизация

## Summary

Titan HUB — функционально насыщенный single-venue POS для анти-кафе/мафия-клубов: почасовая аренда зон, тарифы, миникапы, лояльность, депозиты/долги, аналитика, СБП-эквайринг, планшет-самозаказ из кабинки и встроенный AI-аналитик. По глубине POS-ядра продукт уже конкурентоспособен нишево. Но три вещи блокируют переход к платной SaaS-продаже другим клубам: (1) нет онлайн-бронирования/резерва зон — ключевой спрос анти-кафе и мафия-клубов закрывается у конкурентов, но не здесь; (2) самозаказ работает только с привязанного в зале планшета, нет публичного QR-меню «гость со своего телефона»; (3) нет ни тарифной упаковки, ни биллинга подписки, ни онбординга нового клуба, а изоляция арендатора отсутствует на уровне БД (см. `14-multitenancy-saas.md`). Биллинг времени примитивен: `ceil(минуты/60) × ставка` — нет пакетов/дневных капов/стоп-чека, которые есть в каждом анти-кафе.

## Production-readiness score: 55 / 100

Обоснование: как **single-venue продукт для текущего владельца** ядро готово к коммерческой эксплуатации (отсюда не 30). Но как **тиражируемый SaaS-продукт для продажи другим клубам** не готов: отсутствуют бронирование, публичный QR-самозаказ, тарифная упаковка/биллинг подписки, онбординг, изоляция арендатора (отсюда не 75+). Балл отражает «продуктовую» готовность к коммерции; технический SaaS-блокер вынесен в аудит 14 и здесь дублируется только как зависимость.

## Идеи новых фич (для мафия-клубов / анти-кафе) — по impact/effort

**Высокий impact, средний effort (делать первыми):**
1. **Онлайн-бронирование зон + виджет** (Finding 1). Публичная страница/виджет «выбрать зону, дату, время, число человек», предоплата через уже интегрированную Platega/СБП. Календарь занятости. Это фича №1 для продажи новым клубам и прямой источник предоплат.
2. **Публичный QR-самозаказ «со своего телефона»** (Finding 2). Переиспользует готовый `pending_orders`-конвейер. Растит средний чек без capex на планшеты — сильный аргумент в продаже.
3. **Пакеты/капы тарификации времени** (Finding 3): «3 часа = 600₽», «безлимит вечер = 900₽», «дневной кап», бесплатные первые 15 мин. Прямо повышает выручку клуба и расширяет, кому продукт подходит.

**Высокий impact, низкий effort (quick-ish):**
4. **Лист ожидания на пиковые вечера** (Finding 7) с пушем при освобождении.
5. **Сбор оценок гостя + рейтинг ведущего/вечера** (Finding 4) — поверх Wallet-бота/планшета.
6. **Триггерный CRM**: авто-поздравление с ДР (поле `birthday` уже есть) и реактивация «спящих» (сегмент уже считается) — Finding 10.

**Средний impact, выше effort (после первых):**
7. **Расписание и рейтинг ведущих (host management)** для мафия-клубов (Finding 5): кто ведёт вечер, нагрузка, ставка за вечер, оценка гостей.
8. **Визуальная карта зала / table management** (Finding 6): статус зон в реальном времени, рассадка, бронь на плане.
9. **Турнирная сетка миникапов**: модель миникапа уже есть (`events.ts:78` ростер player/judge), но нет рассадки по столам, раундов, подсчёта очков/рейтинга игроков — естественное расширение для мафия-клуба.
10. **Абонементы/клубные карты**: помесячный безлимит/пакет визитов поверх депозитов — повторяющаяся выручка для клуба, удержание гостя.

## Quick wins (<1 ч)

- **Авто-поздравление с ДР**: поле `profiles.birthday` уже хранится, но не используется. Добавить cron, который раз в день шлёт через Wallet-бот поздравление + бонус подходящим клиентам (инфраструктура `notify`/`push` готова, `events.router.ts:11`). Маленький код — реальный retention.
- **Кнопка «реактивировать спящих»** на дашборде: сегмент `sleeping` уже считается (`analytics.router.ts:824`), не хватает только действия «послать пуш по сегменту». Связать существующий список с существующим push.
- **Использовать `guestNames` для деления счёта** (Finding 11): данные уже на чеке, нужен только UI-сплит на бэке `check_payments` (структура готова, `checks.ts:140`).
- **Текстовый фидбэк после оплаты на планшете**: одно поле + таблица — мгновенный сигнал качества вечера до постройки полного NPS.
- **Шаблоны-пресеты при заведении зон/тарифов**: захардкодить 2 пресета («анти-кафе», «мафия-клуб») как кнопки — частичный онбординг почти бесплатно.

## SaaS / multi-club implications для этой области

- **Жёсткая зависимость от изоляции арендатора** (детально — `14-multitenancy-saas.md`). Все продуктовые фичи ниже (бронирование, QR-самозаказ, рейтинги, CRM-кампании) бессмысленно строить мультиклубно, пока у `spaces`, `checks`, `events`, `profiles`, `reservations` и т.д. нет `tenant_id`. Любую новую таблицу (reservations/feedback/waitlist) сразу проектировать с `tenant_id`, чтобы не переписывать.
- **Тарифная упаковка как продуктовое решение, не только техническое** (Finding 8): рекомендуемая нарезка — *Start* (POS + тарифы + базовая аналитика), *Pro* (бронирование + QR-самозаказ + CRM-кампании + AI-аналитик), *Enterprise* (несколько точек, расширенные права, приоритет-поддержка). Бронирование и AI — естественные «платные» гейты.
- **Онбординг = воронка продаж** (Finding 9): без setup-wizard каждый новый клуб упирается в ручную настройку, что убивает self-serve триал. Это product-задача, а не только инженерная.
- **Конкурентная дифференциация**: против iiko/Poster/r_keeper Titan выигрывает нишевой заточкой (почасовые зоны, миникапы, мафия-ведущие, встроенный AI-аналитик `apps/api/src/modules/ai/ai.router.ts` — 658 строк, реальный tool-use по БД). Это и есть позиционирование: «не очередной ресторанный POS, а система для анти-кафе и мафия-клубов». Бронирование + QR-самозаказ + рейтинг ведущих закрывают разрыв с general-purpose POS, а AI и доменная модель миникапов — то, чего у них нет.
