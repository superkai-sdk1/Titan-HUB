# Titan Home — киоск самообслуживания на Android-планшете

Нативное приложение для планшета в кабинке: гость видит действующий счёт, заказывает из меню, зовёт администратора и пишет ему, платит по QR СБП с чаевыми, оценивает вечер и сам управляет светом и кондиционером кабинки (Home Assistant). Expo SDK 57 (React Native 0.86), без WebView. Веб-версия `/tablet` остаётся как запасной вариант.

- **Код:** `apps/home` (свой `npm`, исключён из pnpm-воркспейса и Docker-контекста)
- **Android:** пакет `ru.titan.home`, только Android (`platforms: ["android"]`)
- **Сервер:** клуб по поддомену, как в Titan HUB (`kbr` → `kbr.titanpos.ru`)
- **Сборка:** `npm run android:device` (Release APK, подпись debug-ключом — для своих планшетов), `EXPO_PUBLIC_LOCAL_STACK=1` — сборка для локального стенда
- **Версия 2.0** (2026-10) — полный рефакторинг: новый интерфейс «стекло», поток событий вместо опросов, работа без сети. План и замеры — [HOME_REFACTOR_PLAN.md](HOME_REFACTOR_PLAN.md).

## Экраны

Гостевая часть — **один экран со слоями**. Слоями управляет визит: счёт закрылся или переехал — всё лишнее закрывается само.

| Экран / слой | Что делает |
| --- | --- |
| Главный | Шапка (логотип — 5 касаний за 3 с для входа сотрудника, кабинка, «нет связи», часы), счёт на весь экран (итог от сервера, разбивка, заказы на подтверждении, позиции) или «Счёт ещё не открыт», три действия: **Меню · Администратор · Оплатить**; у края — язычок панели «Свет и климат» |
| Меню (слой) | Разделы в стеклянной колонке слева («Все», «Популярное», категории), плитки без фото, поиск, плавающая корзина → «Ваш заказ» → отправка администратору. Без открытого счёта — только просмотр |
| Администратор (окно) | «Позвать к столу» и переписка в рамках счёта (быстрые фразы + своё сообщение) — одно место вместо прежних «Позвать» и «Чат». Пока открыта клавиатура, окно стоит над ней, без кнопки вызова и быстрых фраз |
| Оплата (окно) | Чаевые 0/5/10/15 % и QR СБП на одном экране (процент считает сервер); «Принести счёт» — для карты и наличных. Оплату подтверждает банк, экран узнаёт сам |
| Свет и климат (панель) | Только на главном экране (в меню, окнах и на «спасибо» её нет). Свёрнута — язычок у края: справа в альбомной, снизу в книжной (ручка, свет, температура). Панель вытягивают пальцем за язычок или открывают касанием: лампы (вкл/выкл), кондиционер (питание, температура ±, режимы, обдув). Сворачивается обратным движением, касанием фона, «Назад» или сама через 45 с без касаний. При повороте экрана сразу встаёт на место |
| Спасибо и оценка | После закрытия счёта: «Оплата прошла!»/«Счёт закрыт», звёзды → теги → комментарий |
| `setup` | Первая настройка сотрудником: адрес клуба → кабинка → PIN сотрудника. Если сессия истекла — сразу PIN |
| `staff` | Панель сотрудника: кабинка, режим киоска, ориентация, Home Assistant, обслуживание, сброс |
| `staff/booths` | Все кабинки клуба (своя первой): «Перенести сюда» и «Устройства» — единственное место выбора устройств |
| `staff/room` | Выбор устройств Home Assistant для кабинки: до двух групп света и кондиционер, подписи для гостя |

## Визит гостя

1. Планшет держит **один SSE-поток** `GET /api/tablet/stream` — события чеков своей зоны (открыт, позиции, заказ решён, сообщение, оплачен, закрыт, переехал, удалён). На любое событие — `GET /api/tablet/state`.
2. `/api/tablet/state` одним ответом отдаёт открытый счёт зоны с итогом от сервера, заказы на подтверждении, непрочитанные сообщения, мероприятие и судьбу прошлого чека (`previous`: закрыт с суммой оплаты / отменён / переехал / удалён).
3. Машина визита (`features/visit/machine.ts`, покрыта тестами): idle → session → finish → idle. «Оплачено» из потока переводит в благодарность сразу.
4. Запасной таймер: 60 с при живом потоке (живой итог аренды), 10 с — если потока нет. «Зависший» поток (нет даже пингов 70 с) переоткрывается.
5. Гость ушёл посреди меню/переписки — через 2 минуты без касаний слой закрывается, корзина очищается. Окно оплаты не трогаем.
6. **Без сети:** меню и последнее состояние лежат в кэше на диске и видны сразу после перезапуска; свет и климат работают полностью (связь с HA напрямую по LAN).

Сессия скользящая: раз в 3 дня `POST /auth/tablet-refresh` меняет tablet-токен на свежий (30 дней). Если tablet-профиль зоны удалён или зона выключена — 401, и планшет просит PIN сотрудника.

## Интерфейс и производительность

Стиль — в духе Apple Liquid Glass, но **без размытия в реальном времени**: фон киоска статичен (`assets/images/ambient-*.jpg`), стекло — полупрозрачная заливка, светлая верхняя кромка и волосяная граница. Шрифт Inter, линейные иконки lucide.

Правила, проверенные замером на Honor HEY-W09 (Adreno 610): никаких размытых теней (`boxShadow`), бесконечных анимаций и анимаций раскладки в списках; нажатия — через `ui/press.tsx` (отклик на UI-потоке); Home Assistant шлёт в JS только изменения. Эталон 1.0: в простое ~60 перерисовок в секунду и 90–100 % ядра, 57 % рывков в меню — см. HOME_REFACTOR_PLAN.md.

## Режим киоска

Нативный модуль `modules/titan-kiosk` (Kotlin):

| Уровень | Что даёт | Как включить |
| --- | --- | --- |
| Обычный | Полный экран, экран не гаснет, кнопка «Назад» не выпускает из приложения, Titan Home можно выбрать «домашним экраном» | Сразу после установки; «Домой» → выбрать Titan Home → «Всегда» |
| Закрепление экрана | Гость не выйдет кнопками «Домой»/«Недавние» | Панель сотрудника → «Закрепить экран» (Android спросит подтверждение) |
| **Владелец устройства** (рекомендуется) | Закрепление без вопросов при каждом запуске, «Домой» навсегда = Titan Home, шторка уведомлений и экран блокировки отключены, экран не гаснет на зарядке, перезагрузка из панели | Один раз на сброшенном планшете без аккаунтов: `npm run kiosk:owner` (= `adb shell dpm set-device-owner ru.titan.home/expo.modules.titankiosk.KioskAdminReceiver`) |

Вернуть планшет в обычный режим: панель сотрудника → «Снять режим владельца устройства» (только после этого Titan Home можно удалить).

**Падения.** Ошибка в интерфейсе — заглушка «Минуточку…» и перезапуск JS через 2,5 с. Падение процесса — модуль киоска просит Android открыть Titan Home снова через 2 с (не чаще трёх раз в минуту); если Titan Home — домашний экран, Android вернёт его и сам.

Ориентация по умолчанию — «Как планшет»: на больших экранах Android не поворачивает дисплей под приложение, а сужает его полосой, поэтому фиксировать альбомную/книжную стоит, только если планшет так и стоит. Поворот закрепляют в настройках Android.

## Home Assistant

Планшет сам, **на уровне Android**, подключается к Home Assistant по локальной сети долгосрочным токеном — адрес и токен вбиваются в Titan HUB. Связь держится **постоянно**.

- **Где настраивается.** Адрес и токен — интеграция клуба «Home Assistant» в Titan HUB: «Управление» → «Настройки» → «Интеграции» (ключи `ha_url`, `ha_token`, хранятся зашифрованно). Планшет получает их `GET /pos/tablet/smart-home` — осознанное исключение из правила «секреты не покидают сервер». Устройства кабинки (до двух `light.*`/`switch.*`/`input_boolean.*` и одна `climate.*`) выбирает сотрудник на самом планшете (`staff/room`, список из HA `get_states`); сохраняется в зоне: `spaces.smart_home`, `PUT /pos/tablet/smart-home` (только своя зона). **Создайте в HA отдельного пользователя без прав администратора** и выпустите токен от его имени.
- **Кто держит связь.** Нативный модуль `modules/titan-ha` (Kotlin): WebSocket API HA (`ws://<ha>:8123/api/websocket`) через OkHttp в своём потоке, подписка `subscribe_entities`, команды `call_service`/`get_states`. Его держит foreground-сервис Android `HaService` (тип `connectedDevice`, тихое уведомление «Умный дом подключён», Wi-Fi-lock и wake-lock): соединение живёт, даже когда экран Titan Home свёрнут (сотрудник в настройках Android) или интерфейс перезапущен.
- **Связь не зависит от сервера Titan.** Адрес, токен и устройства сохраняются на планшете (настройки приложения; конфигурация панели — в Keystore). Если сервер Titan недоступен, планшет продолжает управлять светом и климатом. Связь разрывается, только если Home Assistant убрали из интеграций клуба или планшет отвязали от клуба.
- **Восстановление.** Обрыв — переподключение с паузой 1→30 с; появилась сеть — сразу (колбэк сети Android); «зависшее» соединение ловят пинги WebSocket каждые 20 с и пинги HA каждые 30 с; Android убил процесс — сервис поднимается сам (`START_STICKY`); перезагрузка или обновление приложения — сервис стартует сам (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`) ещё до открытия экрана. Неверный токен — без повторов, статус «Нет доступа». В панели сотрудника — статус и кнопка «Переподключить».
- **Экран** только показывает состояние и отправляет команды. Натив шлёт в JS лишь изменения: `onStatus` (статус связи) и `onEntities` (изменившиеся устройства, склейка за 100 мс) — перерисовывается одна плитка, а не вся панель. Результат команды виден сразу, с откатом при ошибке. Пока связь переподнимается, команда ждёт в очереди до 10 с, а не превращается в «мёртвую» кнопку. Последний рабочий режим кондиционера хранится на планшете — «включить» возвращает его и после перезапуска. Команды: `light|switch|input_boolean.turn_on/turn_off`, `climate.set_hvac_mode`, `climate.set_temperature`, `climate.set_fan_mode`.
- Для `http://` разрешён незашифрованный трафик (`usesCleartextTraffic`).
- Опция панели сотрудника «Выключать после счёта»: когда счёт закрыт, планшет гасит свет и выключает кондиционер.

Проверено на стенде: минута в фоне без разрывов, перезапуск HA (переподключение за доли секунды), убийство процесса (сервис поднялся и подключился через 2 с без экрана), перезагрузка (подключение через 4 с после загрузки, экран не открывался), пропадание Wi-Fi на 40 с (переподключение в ту же секунду, как вернулась сеть).

## Кабинки: перенос планшета и пресеты устройств

У каждой кабинки свой пресет умного дома (`spaces.smart_home`). Планшет переносят в другую кабинку **без повторной настройки**: панель сотрудника → «Кабинка · …» → «Перенести сюда». Планшет получает tablet-токен новой зоны, экран гостя начинает визит с нуля, а нативное соединение с Home Assistant переключается на устройства новой кабинки. Там же — «Устройства» любой кабинки: пресеты всех кабинок настраиваются с одного планшета, не перенося его.

После PIN сотрудника `/auth/tablet-session` выдаёт вместе с tablet-токеном **служебный токен** (роль `tablet-staff`, 15 минут, только в памяти планшета). Эту роль не принимает ни один маршрут кассы — только:

- `POST /auth/tablet-switch {spaceId}` — перенос: новая сессия планшета для зоны и новый служебный токен;
- `GET /pos/tablet/booths` — активные кабинки с устройствами;
- `PUT /pos/tablet/booths/:spaceId/smart-home` — устройства любой кабинки.

Панель закрылась или токен истёк — нужен PIN заново.

## Оценка вечера

`POST /pos/checks/:id/feedback {rating 1–5, tags[], comment?}` — только закрытый чек своей зоны, в течение 6 часов после закрытия; повторная отправка перезаписывает (`guest_feedback`, уникальный `check_id`). Оценка ≤ 3★ или с комментарием → уведомление персоналу типа `guest_feedback` (отключается в настройках уведомлений). Владелец видит отзывы в аналитике: вкладка «Отзывы» (`GET /analytics/feedback?from&to` — средняя, распределение, теги, лента).

## Серверные маршруты 2.0

- `GET /api/tablet/state[?checkId=]`, `GET /api/tablet/stream`, `GET /api/tablet/menu` (ETag) — только роль `tablet`, модуль `apps/api/src/modules/tablet`.
- `POST /pos/checks/:id/qr` принимает `tipPercent` (0–30) — чаевые считаются от серверного итога.
- Старые маршруты `/pos/*` для планшета не менялись: веб-киоск `/tablet` и APK 1.x работают как прежде.

## Серверные изменения (миграция 066)

- `guest_feedback` — оценки; `spaces.smart_home jsonb` — устройства Home Assistant зоны.
- `POST /auth/tablet-refresh`, `GET/PUT /pos/tablet/smart-home`, `POST /pos/checks/:id/feedback`, `GET /analytics/feedback`.
- Интеграции `ha_url`, `ha_token`; тип уведомления `guest_feedback`.

## Проверка на стенде

Локальный стенд: Postgres 16 + API из `apps/api/dist` на `:3901` + Redis (fakeredis с командой `INFO`) + имитатор Home Assistant (WebSocket на `:8123`). Сборка `EXPO_PUBLIC_LOCAL_STACK=1`, адрес клуба в приложении — `10.0.2.2:3901` для эмулятора или `192.168.x.x:3901` для планшета в Wi-Fi.
